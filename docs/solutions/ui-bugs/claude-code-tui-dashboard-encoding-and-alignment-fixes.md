# CLI Dashboard: Windows Encoding & Rich Markup Alignment Fixes

## Problem

Built a CLI dashboard (`cli.py`) using `textual` (tabbed TUI) and `rich` to display Claude Code usage statistics in the terminal. Two display bugs appeared during development:

1. **Windows cp1252 encoding crash** — Unicode block characters (`█`, `░`, `●`) caused `UnicodeEncodeError` on Windows terminals defaulting to cp1252.
2. **Rich markup column misalignment** — Python f-string format specs (`:>10`, `:<25`) count invisible rich markup tags (`[green]`, `[/]`) as visible characters, breaking table column alignment.

### Symptoms

```
UnicodeEncodeError: 'charmap' codec can't encode characters in position 0-34: character maps to <undefined>
```

And visually shifted columns in the Installed Plugins table on the Insights tab.

## Solution

### Architecture

The TUI app is structured as a **Textual `App`** with `TabbedContent` providing 7 switchable tabs: Overview, Tokens, Activity, Projects, Sessions, Plan & Billing, and Insights. Each tab's content is generated by a dedicated `build_*_text()` function that returns a string with rich markup, rendered inside `Static` widgets wrapped in `VerticalScroll` containers. A persistent KPI bar sits above the tabs.

Data flow: `main()` calls `maybe_refresh()` (auto-runs `extract_stats.py` if data is stale/missing), loads `dashboard_data.json`, then either launches the TUI or prints to stdout depending on flags (`--print`, `--all`, `--section`, `--json`).

### Fix 1: Windows UTF-8 Encoding

Wrap `sys.stdout` and `sys.stderr` before any output happens:

```python
import sys, io, os

if sys.platform == "win32":
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding="utf-8", errors="replace")
    os.environ.setdefault("PYTHONIOENCODING", "utf-8")
```

This runs at module level (before imports that may produce output), forcing UTF-8 with graceful fallback via `errors="replace"`.

### Fix 2: Rich Markup Column Alignment

**Wrong** — format spec counts markup tags as visible width:
```python
status = f"[green]●[/]"  # 12+ chars internally, 1 char visible
f"  {p['name']:<25} {status:>6}  {version:<14}"  # columns shift
```

**Correct** — pad the visible text first, then wrap with markup (or don't align markup strings at all):
```python
dot = f"[green]● Active[/] "  # fixed visible width with manual spacing
f"  {p['short_name']:<25} {dot} {version:<14} {date:<10}"
```

Or for numeric values, pad the plain value then wrap:
```python
f"{C_GREEN}{fmt_cost(m['cost']):>10}[/] "
# fmt_cost returns "$16.96", padded to 10 chars, THEN wrapped in color
```

### Key Implementation Patterns

**Bar chart helper:**
```python
def make_bar(val, max_val, width=30):
    if max_val <= 0:
        return ""
    filled = int(val / max_val * width)
    return "\u2588" * filled + "\u2591" * (width - filled)
```

**TUI compose method:**
```python
def compose(self) -> ComposeResult:
    yield Header()
    yield Static(build_kpi_text(self.data), id="kpi-bar")
    with TabbedContent("Overview", "Tokens", "Activity", ...):
        with TabPane("Overview"):
            yield VerticalScroll(Static(build_overview_text(self.data)))
        # ... one TabPane per section
    yield Footer()
```

**Auto-refresh logic:**
```python
def maybe_refresh(no_refresh):
    if no_refresh:
        return
    if not DATA_FILE.exists():
        subprocess.run([sys.executable, str(EXTRACT_SCRIPT)], check=True)
        return
    age = time.time() - os.path.getmtime(str(DATA_FILE))
    if age > 600:
        subprocess.run([sys.executable, str(EXTRACT_SCRIPT)], check=True)
```

### What Didn't Work

1. **Initial version used `rich.Console` only (no tabs)** — dumped all sections sequentially, overwhelming for large datasets. Switched to Textual's `TabbedContent` for navigable sections.
2. **Block characters crashed on Windows** — `█` and `░` are not representable in cp1252. Fixed with the `io.TextIOWrapper` wrapping.
3. **Format-spec alignment broke with markup** — `f"{C_GREEN}{value}{C_END}":>10}` doesn't work. Solution: pad plain value first, wrap with tags after.

## Prevention & Best Practices

### Always Force UTF-8 on Windows Early

The in-script wrapper is the only reliable defense — `PYTHONUTF8=1` env var and `python -X utf8` are not under your code's control.

### Never Use Python Format-Spec Alignment on Markup Strings

| Pattern | Works? |
|---|---|
| `f"{styled_string:>10}"` | No — counts markup chars |
| `f"[green]{plain_string:>10}[/]"` | Yes — pad first, wrap after |
| `Rich.Table` with `justify="right"` | Yes — markup-aware alignment |
| `rich.text.Text.rjust()` | Yes — measures visible width |

**Rule of thumb:** If a string contains `[` or `]` bracket markup, never use f-string format specs for alignment.

### Testing Checklist for Cross-Platform TUI

| Layer | What to test | How |
|---|---|---|
| Encoding | Every print path handles non-ASCII | Monkeypatch stdout to cp1252, assert no UnicodeEncodeError |
| Alignment | Column output has correct visible widths | Capture Console output to StringIO, strip ANSI, check lengths |
| Platform | Runs on Win/Mac/Linux | CI matrix: `runs-on: [ubuntu-latest, windows-latest, macos-latest]` |

### Project-Level Patterns

- Prefer `Rich.Table` over hand-rolled column formatting — it handles markup-aware padding automatically
- Pin `PYTHONUTF8=1` in `.env` and CI config as belt-and-suspenders
- Ban raw f-string alignment on styled strings via pre-commit hook
